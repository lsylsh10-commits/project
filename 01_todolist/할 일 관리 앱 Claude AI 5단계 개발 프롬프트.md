# 할 일 관리 앱 Claude AI 5단계 개발 프롬프트

아래 프롬프트는 할 일 관리 앱 PRD를 기반으로 Claude AI에서 단계적으로 개발하기 위한 프롬프트이다.

각 단계는 이전 단계의 결과물을 기준으로 이어서 진행한다.

---

# STEP 1. 프로젝트 구조 및 기능 설계

## 목적

PRD를 분석하여 앱의 전체 구조와 기능 범위를 먼저 확정한다.

이 단계에서는 실제 코드를 작성하지 않고 화면 구조, 기능, 데이터 흐름을 설계한다.

## Claude AI 프롬프트

너는 30년 경력의 앱 서비스 기획자이자 UX 설계 전문가야.

아래 요구사항을 기준으로 모바일 중심의 할 일 관리 앱을 설계해줘.

이 단계에서는 아직 실제 개발 코드를 작성하지 말고, 앱의 기능 구조와 화면 구조를 먼저 명확하게 정의해줘.

### 앱의 핵심 목적

사용자가 오늘 해야 할 일을 빠르게 확인하고 등록하며 완료 여부를 관리할 수 있는 개인용 할 일 관리 앱을 제작한다.

복잡한 생산성 도구가 아니라 직관적이고 사용하기 쉬운 앱을 목표로 한다.

### 핵심 기능

다음 기능은 반드시 포함한다.

- 할 일 등록
- 할 일 수정
- 할 일 삭제
- 완료 체크
- 날짜 설정
- 시간 설정
- 중요 일정 표시
- 카테고리 관리
- 오늘 할 일
- 진행률 표시
- 검색
- 필터
- 달력
- 완료 기록
- 설정

### 주요 화면

다음 화면을 기본 구조로 사용한다.

1. Home
2. Add Todo
3. Todo Detail / Edit
4. Calendar
5. History
6. Settings

### 하단 네비게이션

다음 구조를 사용한다.

- 홈
- 일정
- 할 일 추가
- 기록
- 설정

가운데 할 일 추가 버튼은 가장 중요한 Primary Action으로 구성한다.

### UX 원칙

사용자는 앱을 실행한 뒤 3초 이내에 오늘 해야 할 일을 확인할 수 있어야 한다.

할 일 등록 시 필수 입력은 다음 두 가지로 제한한다.

- 할 일 제목
- 날짜

시간, 카테고리, 중요도, 메모 등은 선택 입력으로 구성한다.

### 요구 결과물

다음 내용을 순서대로 작성해줘.

1. 앱 전체 정보 구조
2. 화면별 역할
3. 각 화면에 필요한 UI 요소
4. 사용자 주요 행동 흐름
5. Todo 데이터 구조
6. MVP 기능
7. 추후 확장 기능
8. 화면 간 이동 구조

아직 코드를 작성하지 말 것.

기능을 임의로 과도하게 추가하지 말고 위 요구사항을 기준으로 실제 구현 가능한 구조로 설계해줘.

# STEP 2. 디자인 시스템 및 UI 스타일 정의

## 목적

앱 전체에서 사용할 컬러, 타이포그래피, 버튼, 카드, 태그 등 디자인 시스템을 확정한다.

## Claude AI 프롬프트

STEP 1에서 정의한 앱 구조를 그대로 유지해줘.

기능이나 화면 구조를 임의로 변경하지 말고 이번 단계에서는 UI 디자인 시스템만 설계한다.

전체 디자인 방향은 다음과 같다.

### 디자인 컨셉

Toss처럼 깔끔하고 여백이 충분한 UI를 기반으로 하되 일반적인 생산성 앱보다 조금 더 프리미엄하고 브랜드 감성이 느껴지도록 제작한다.

디자인 키워드:

- Clean
- Premium
- Modern
- Editorial
- Calm
- Productivity

화면에 불필요한 박스나 장식을 많이 사용하지 않는다.

화이트 공간을 충분히 사용하고 정보 위계를 명확하게 표현한다.

## 개발 원칙

컴포넌트와 데이터 로직을 명확하게 분리한다.

파일명과 폴더명을 이해하기 쉽게 작성한다.

필요하지 않은 라이브러리는 사용하지 않는다.

모바일 화면을 우선으로 구현한다.

## 최종 검수 기준

다음 조건을 모두 만족해야 한다.

- 모든 버튼이 실제로 작동한다.
- Todo CRUD가 정상 작동한다.
- 완료율 계산이 정확하다.
- 필터와 검색이 정상 작동한다.
- 데이터가 유지된다.
- 모바일 화면이 깨지지 않는다.
- 컬러 시스템이 일관된다.
- 불필요한 기능이 추가되지 않았다.
- 중복 코드가 최소화되었다.
- Console Error가 없다.

## 최종 결과물

검수 완료 후 다음 내용을 제공해줘.

1. 발견된 문제
2. 수정한 내용
3. 최종 기능 목록
4. 최종 파일 구조
5. 실행 방법
6. 추가 개발이 가능한 기능

기존에 정상적으로 작동하는 부분은 임의로 수정하지 말고 필요한 부분만 최소한으로 변경해줘.
